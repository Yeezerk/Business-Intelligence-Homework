     ↓

## 二、数据与问题定义

### 数据集
- **来源**：Kaggle 2023 Credit Card Fraud Detection
- **原始规模**：56.8 万条，正负接近 1:1（非真实场景）
- **处理后**：下采样正常交易至 150,000，欺诈 750 条 → **0.5% 欺诈率（1:200）**
- **特征**：29 维（28 个 PCA 匿名化 V1-V28 + Amount），无缺失值

### 核心挑战
1. **极度不平衡**：0.5% → 准确率完全失效（预测全正常=99.5%），必须用 AUPRC
2. **PCA 匿名化**：特征无业务语义 → 模型不能依赖先验知识，只能从数值模式学习
3. **真实业务约束**：漏报（FN）成本 >> 误报（FP）成本（10:1）

### 评估指标选择

| 指标 | 特点 | 本项目取值 |
|------|------|-----------|
| **AUPRC**（主要） | 聚焦正类（欺诈），对不平衡敏感 | 0.898~0.950 |
| ROC-AUC | 受 TN 主导，区分度低 | 0.992~0.999 |
| **ECE** | 概率校准质量，反映"预测 0.8 是否真≈80% 是欺诈" | 0.0006~0.039 |
| **Cost** | 业务成本 = FP×1 + FN×10 | 99~215 |

## 三、模型原理（答辩核心）

### 3.1 XGBoost（基线/教师）

**核心思想**：梯度提升树，每棵树拟合上一棵树的残差。

**为什么表格数据上强**：
- 轴对齐分裂（axis-aligned split）：每次分裂沿单一特征维度判断 `x_i > t`
- 天然适合表格数据——特征本身就是轴对齐的（每列有独立含义）
- 对无信息特征不敏感——分裂只选最有信息量的维度和阈值
- 不受旋转影响——其他特征的尺度变化不影响当前特征的分裂

**本文配置**：300 棵树，深度 8，lr=0.05，`scale_pos_weight` 自动调节类别权重

### 3.2 FT-Transformer（注意力基线）

**一句话**：把 29 个特征当作 29 个"词"，用 Transformer 让它们互相交流。

**四层架构**：

```
┌─ 第 1 层：Feature Tokenizer ────────────────────────────┐
│ 每个特征 j 有专属嵌入向量 W_j∈R^64                      │
│ T_j = x_j · W_j + b_j    （标量→64 维向量）            │
│ 不同特征不同方向 → 为注意力提供可区分的 Query/Key       │
├─ 第 2 层：[CLS] Token ──────────────────────────────────┤
│ 前置可学习向量 T_CLS，经过注意力后汇聚所有特征信息       │
│ 本质：模型学到的"最佳问题"，向各特征"提问"              │
├─ 第 3 层：Multi-Head Self-Attention（8 头 × 3 层）────┤
│ Q,K,V = Z·W_Q, Z·W_K, Z·W_V                             │
│ Attention = Sparsemax(QK^T/√d_k) · V                     │
│ 30×30 矩阵 → 每对特征间有注意力权重                     │
├─ 第 4 层：分类头                                        │
│ [CLS]→LayerNorm→Linear(64→1)→Sigmoid                     │
└──────────────────────────────────────────────────────────┘
```

**本文关键改进 — Sparsemax**：
- Softmax 问题：每个输出必 > 0（e^z > 0 恒成立），PCA 空间中所有内积接近 → 均匀分布
- Sparsemax：欧氏投影到概率单纯形，产生**可能为零**的稀疏分布
- 公式：`Sparsemax(z)_i = max(z_i - τ(z), 0)`，其中 τ 确保和=1
- 效果：AUPRC 0.8401→**0.9179**，ECE 0.2328→**0.0120**，Cost 269→**99**

### 3.3 DeepFM（交互基线）

**一句话**：同时做"显式"两两特征交互（FM）和"隐式"高阶表示（MLP），两路共享嵌入。

**三路架构**：

```
共享嵌入层：e_i = x_i · v_i ∈ R^16   （每个特征 16 维）
      │
      ├── FM 一阶：w_0 + Σ w_i x_i              （线性，等价逻辑回归）
      ├── FM 二阶：½ Σ[(Σ v_i,f x_i)² − Σ v_i,f² x_i²]
      │   核心技巧：O(D²K)→O(DK)，利用 (Σa_i)² = Σa_i² + 2Σ_{i<j}a_i a_j
      └── Deep：Concat(e_1...e_29)→MLP([256,128,64])→ReLU+Dropout

最终：σ(w_0 + FM₁ + FM₂ + Deep_Mout·h₃)
```

**为什么在 PCA 空间优于 FTT**：
1. FM 交互是 `⟨v_i, v_j⟩ · x_i · x_j` 的静态三因子乘积——不依赖动态 Query-Key 上下文
2. PCA 匿名化使 FTT 的 Query-Key 内积趋同，但 FM 的嵌入内积是对齐程度的静态度量
3. 梯度路径短且稳定：直接乘积 vs 经过 Softmax/Sparsemax + V 加权 + 残差

## 四、创新点详解

### 4.1 Sparsemax 替代 Softmax

**问题诊断**：FT-Transformer 注意力权重全部落在 [0.0327, 0.0342]，标准差仅 0.0004，与均匀分布 1/29=0.0345 几乎重合 → **注意力塌缩**

**原因**：PCA 使特征嵌入向量在空间中高度同质化，所有 Query-Key 内积接近 → Softmax 后几乎均匀

**Sparsemax 原理**：
```
Softmax(z)_i = e^z_i / Σ e^z_j    → 永远 > 0，低差异时 ≈ 1/d
Sparsemax(z)_i = max(z_i - τ, 0)  → 可以 = 0，强制做选择
```
本质：找到"一刀切"阈值 τ，低于 τ 的 logit 被直接舍弃。

**实证效果**：
| 指标 | Softmax FTT | Sparsemax FTT |
|------|------------|---------------|
| AUPRC | 0.8401 | **0.9179** |
| ECE | 0.2328 | **0.0120** |
| Cost | 269 | **99** |

### 4.2 Tree-Supervised 知识蒸馏

**动机**：XGBoost 天然知道特征重要性（split gain），FTT/DeepFM 要从零学。能否"以树为师"？

**方案 3A — 软标签蒸馏**：
```
L_total = α·FL(student_logits, y_true) + (1-α)·T²·KL(student_probs^T || teacher_probs^T)
```
- T=4.0：温度软化，让教师输出的概率分布更平滑，传递"暗知识"
- α=0.7：70% 看真实标签，30% 模仿老师
- KL 散度：度量两个概率分布的距离

**方案 3B — 特征重要性正则化**：
```
L_reg = λ · Σ_i (1 - w_i) · ||E_i||₂
```
- w_i：XGBoost 的 split gain 归一化 → V14=1.0, V12=0.07, V4=0.059
- 效果：高重要性特征允许大嵌入范数，低重要性特征被压缩

**关键结果（核心答辩亮点）**：

| 模型 | AUPRC | vs 基线 | ECE | 结论 |
|------|-------|---------|-----|------|
| DeepFM+KD | **0.9495** | +1.6pp | 0.0008 | ✅ 蒸馏成功 |
| FTT+KD+TreeReg | 0.8974 | **-2.1pp** | 0.0010 | ❌ 蒸馏失败 |

**为什么 DeepFM+KD 成功但 FTT+KD 失败？**
- DeepFM 的一阶线性项 `w_i x_i` 与 XGBoost 的轴对齐分裂同构 → 软标签信号无损注入 FM 空间
- FTT 的自注意力无视特征轴 → 树先验与注意力形成结构性冲突（轴对齐 vs 全局自注意力）
- 方案 3B 强制 FTT 嵌入层模仿 V14=1.0 的特征偏好 → 与 Sparsemax 的自由特征选择拮抗

> **答辩金句**：蒸馏不是"即插即用"的黑盒——它与目标架构的归纳偏置高度耦合。对交互型架构是催化剂，对注意力型架构是枷锁。

## 五、完整结果总表

| 排名 | 模型 | AUPRC | F1 | Cost | ECE |
|------|------|-------|-----|------|-----|
| 🥇 | DeepFM + KD | 0.9495 | 0.9058 | 120 | 0.0008 |
| 🥈 | DeepFM | 0.9336 | 0.8938 | 123 | 0.0394 |
| 🥉 | XGBoost | 0.9331 | 0.8750 | 215 | 0.0006 |
| 4 | FT-Transformer | 0.9179 | 0.9196 | 99 | 0.0120 |
| 5 | FTT + KD + TreeReg | 0.8974 | 0.8848 | 169 | 0.0010 |

### 答辩时可按需展开的分析维度：

1. **AUPRC vs ROC-AUC**：三模型 ROC-AUC 0.9925-0.9979（极差 0.0054，几乎无法区分），但 AUPRC 0.898-0.950 → 不平衡场景必须用 AUPRC
2. **成本-精度非单调**：FTT 成本最低（99），但 AUPRC 排第 4；XGBoost 成本最高（215）
3. **SHAP 分析**：V14 的 SHAP 值（0.6784）是第二名 V12（0.0475）的 14.3 倍 → 单特征主导
4. **FTT 注意力**：即使 Sparsemax，注意力分布仍接近均匀 → PCA 空间本身缺乏注意力可利用的语义结构

## 六、实验设计关键决策

### 种子可复现性
- 每个模型训练前调用 `reset_seed(SEED)`：重置 random/numpy/torch/cuda 全部状态
- 原因：pytorch-tabnet 的 `.fit()` 内部消耗随机状态，影响后续模型初始化
- 这是学术严谨性的要求——reproducible results

### 损失函数选择
- FTT（Sparsemax）：Focal Loss α=0.25 —— 稀疏注意力需要均衡梯度
- DeepFM：Focal Loss α=0.995（类别反比）—— 无内置稀疏机制，靠强加权
- KD 训练：Focal Loss（70%）+ KL 散度（30%），T=4.0

### 何时用哪个指标
- **AUPRC**：不平衡分类的首选（主指标）
- **ECE**：概率校准质量（生产环境用概率打分时关键）
- **Cost**：业务决策（FP=1, FN=10——漏报更昂贵）
- **ROC-AUC**：便于与文献对比（非主指标）

## 七、潜在答辩问题及应对

### Q1：为什么不用 SMOTE？
**A**：PCA 匿名化后，SMOTE 在特征空间中线性插值会破坏协方差结构，生成不符合真实分布的样本。实验显示 SMOTE 使 AUPRC 降至 0.78（我们的基线 0.87）。

### Q2：FTT 用了 Sparsemax，TabNet 也用了 Sparsemax，为什么不比 TabNet？
**A**：TabNet 的序列稀疏注意力和 FTT 的全局自注意力代表不同范式。本文聚焦于"纯自注意力 vs 显式特征交互"的对比。TabNet 作为序贯模型介于两者之间，更多特征选择而非特征交互。我们在早期实验中包含了 TabNet（AUPRC=0.864），但论文聚焦于归纳偏置迁移的可控实验，故移除以精简叙事。如需引用，可提其 Sparsemax 设计启发了本文对 FTT 的改进。

### Q3：DeepFM+KD 只用了 3A（软标签），为什么不用 3B（TreeReg）？
**A**：设计选择——TreeReg 是为注意力架构设计的，目标是将树特征偏好"强制注入"到注意力机制中。DeepFM 的一阶线性项已经天然对齐了 XGBoost 的轴偏好，加 TreeReg 会导致"双重正则化"反效果。实验验证了这个判断——DeepFM+KD 单独用软标签蒸馏已取得最优结果。

### Q4：FTT+KD 到底有效还是无效？TreeReg 为什么有害？
**A**：FTT+KD（**仅 3A，不含 TreeReg**）非常有效——AUPRC=0.9347（+1.68pp vs FTT 基线），ECE=0.0007（近乎完美）。真正有毒的是 TreeReg（3B）：它在 FTT 的嵌入层上施加了 XGBoost 的轴对齐特征偏好（V14 权重=1.0，其余≈0），强制模型忽略 28/29 的特征维度——这将 FTT 从 0.9347 断崖拖降至 0.8974（-3.73pp）。结论：**软标签蒸馏是跨架构安全且高效的；嵌入层正则化对注意力型架构是精确的"毒药"**。

### Q5：为什么只跑了一个随机种子？
**A**：这是本文的核心局限之一。理想实验设计需要 ≥15 个随机种子、报告均值和置信区间、Wilcoxon 检验。但 GPU 训练（RTX 4060 8GB）每个模型约 30 分钟，全量多种子实验需要数天。论文在讨论章节明确标注了这一局限，并建议未来工作补充统计检验。

### Q6：DeepFM 比 XGBoost 好 0.0005，这个差距有意义吗？
**A**：从统计角度没有——0.0005 的差距在单一种子下不具统计显著性（论文已将表述修正为"统计上不可区分"）。但有意义的比较是：（1）**FTT+KD（0.9347）vs DeepFM+KD（0.9495）vs XGBoost（0.9331）**——蒸馏后的两种深度模型均实质性超越了 XGBoost；（2）**FTT+KD（+1.68pp）vs FTT+KD+TreeReg（-3.73pp）**——同一个消融对照清晰地隔离了 TreeReg 的破坏性效应。核心叙事不是"深度 vs 树谁更好"，而是"KD 跨架构有效，TreeReg 对注意力有毒"。
