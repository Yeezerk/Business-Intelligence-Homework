# 07 — SHAP 模型可解释性

> **核心问题**：模型说这笔交易是欺诈，但"为什么"？SHAP 基于博弈论中的 Shapley 值，为每个特征公平地分配对预测结果的贡献。

---

## 1. 为什么可解释性在金融风控中至关重要？

### 1.1 监管合规

- GDPR（欧盟通用数据保护条例）要求自动化决策系统提供"有意义的解释"
- 美国的公平信贷报告法（FCRA）要求对拒绝决策提供理由
- 中国《个人信息保护法》也包含类似条款

### 1.2 业务信任

风控分析师不会盲目相信一个黑箱模型：
- "这笔 5000 元的交易为什么被拦？"
- "上次类似的特征组合为什么放行了？"
- "这个特征权重是否符合我的领域经验？"

### 1.3 模型调试

当模型出错时（漏掉大额欺诈），可解释性帮助定位问题：
- 是否某个特征被过度依赖？
- 是否有数据泄露导致的虚假特征重要性？

## 2. Shapley 值的直觉

### 2.1 类比：三人分蛋糕

Alice、Bob、Charlie 一起烤了一个蛋糕。如果没有 Alice，蛋糕价值降低 \$30；没有 Bob 降低 \$20；没有 Charlie 降低 \$10。如何公平分配？

答案：计算每个人在所有可能的加入顺序中的边际贡献均值。

### 2.2 转化为模型解释

特征 = 参与方，模型输出 = 蛋糕价值。

对于特征 $j$，其 Shapley 值：

$$\phi_j = \sum_{S \subseteq F \setminus \{j\}} \frac{|S|! (|F| - |S| - 1)!}{|F|!} \left[ f(S \cup \{j\}) - f(S) \right]$$

**公式各部分含义**：

| 符号                                               | 含义                                      |
| -------------------------------------------------- | ----------------------------------------- |
| $\phi_j$                                           | 特征 j 的 Shapley 值——归因给特征 j 的贡献 |
| $F$                                                | 所有特征的集合                            |
| $S \subseteq F \setminus \{j\}$                    | 遍历所有不包含 j 的子集 S                 |
| $\frac{\|S\|! \cdot (\|F\| - \|S\| - 1)!}{\|F\|!}$ | 权重系数，反映子集 S 的代表性             |
| $f(S \cup \{j\}) - f(S)$                           | 加入特征 j 后的边际贡献                   |

**权重系数的直觉**：特征 j 以不同顺序加入的场景中，权重反映了子集 S 的"代表性"——子集 S 越大（越接近完整集合），权重越高。

**边际贡献**：$f(S)$ 是仅用特征子集 S 时的预测，$f(S \cup \{j\})$ 是加入特征 j 后的预测，差值即特征 j 的边际增益。

### 2.3 为什么 Shapley 值"公平"？

Shapley 值满足四个公理：
1. **效率**：所有特征的贡献之和 = 预测值 - 平均预测值
2. **对称性**：如果两个特征在所有子集中贡献相同，则获得相同值
3. **虚拟性**：如果一个特征从不贡献，则值为 0
4. **可加性**：SHAP(模型A+B) = SHAP(模型A) + SHAP(模型B)

没有其他归因方法同时满足这四个公理。

## 3. SHAP 计算方法

### 3.1 为什么要用专门的算法？

直接用公式计算，对于 30 个特征：
- 每个特征有 $2^{29} \approx 2.68$ 亿个子集
- 30 个特征 × 2.68 亿 = **约 80 亿次计算**

三种算法各有"窍门"来避免这个指数级复杂度问题。

### 3.2 TreeSHAP（树模型专用）

**核心思路**：利用树模型的特殊结构，不枚举子集，用动态规划直接数学推导。

对于 XGBoost/Random Forest 等树模型，TreeSHAP 可以在 $O(TLD^2)$ 时间内精确计算（$T$=树数, $L$=叶数, $D$=特征数）。

**关键洞察**：决策树的预测只沿着一条路径走，不需要遍历所有 $2^{|F|}$ 个子集。

**计算流程**：
1. **预计算**：每棵树的每个节点存储样本数量、特征条件、输出值
2. **条件期望**：对"给定特征子集 S 时，输出的期望值"进行计算，而不是对每个子集单独计算 $f(S)$
3. **动态规划**：从叶子节点向上回推，快速计算各特征的 Shapley 值

**复杂度对比**：对于 30 特征、100 棵树、深度 10：
- 原始公式：$2^{30} \approx 10$ 亿
- TreeSHAP：$100 \times 10 \times 30^2 = 90$ 万

```python
import shap
explainer = shap.TreeExplainer(xgb_model)
shap_values = explainer.shap_values(X_test)
```

### 3.3 KernelSHAP（通用方法）

**核心思路**：用采样和线性回归代替精确计算——用统计估计代替穷举。

对任何黑箱模型（包括神经网络），KernelSHAP 通过对特征子集采样来估计 Shapley 值。

**计算流程**：
1. **采样**：从 $2^{|F|-1}$ 个子集中随机采样 N 个（通常 100-500 个）
2. **计算边际贡献**：对每个采样子集 S，计算 $f(S \cup \{j\}) - f(S)$
3. **加权回归**：建立线性模型 $\phi_j = \sum_k w_k \cdot [f(S_k \cup \{j\}) - f(S_k)]$，其中权重 $w_k$ 来源于 Shapley 值的理论权重公式
4. **求解系数**：通过最小二乘法求出每个特征的 $\phi_j$

**类比**：原始方法 = 精确称量 100 亿粒米；KernelSHAP = 随机舀 500 勺，根据这 500 勺推断总重

```python
explainer = shap.KernelExplainer(model.predict, background_data)
shap_values = explainer.shap_values(X_test)
```

**注意**：KernelSHAP 计算量巨大，通常只用 100-500 个背景样本，存在估计误差。

### 3.4 DeepSHAP / GradientExplainer

**核心思路**：借鉴反向传播思想，像求梯度一样求归因，一次传播搞定所有特征贡献。

对于深度学习模型，DeepSHAP 结合了 SHAP 和 DeepLIFT，通过反向传播计算特征贡献。

**为什么 KernelSHAP 对神经网络不实用？**：100 层网络每次前向传播代价高昂，再用 KernelSHAP 采样上万个子集 → 几乎不可能。

**计算流程**：
1. **定义参考值**：选择有代表性的背景数据集（如训练数据均值）作为 baseline $x_{ref}$
2. **前向传播**：将输入 $x$ 和参考值 $x_{ref}$ 都前向传播一次，记录所有层的激活值 $a^{[l]}$ 和 $a_{ref}^{[l]}$
3. **反向归因**：从输出层开始，用链式法则把贡献分配到输入层

$$\Delta a^{[l]} = a^{[l]} - a_{ref}^{[l]}$$

4. **逐层分解**：$\phi_j = \sum_{l} \frac{\partial f}{\partial a^{[l]}} \cdot \Delta a_j^{[l]}$，类似求梯度但计算的是 Shapley 值

**类比**：传统方法 = 分别敲击钢琴每个位置来测量音高（敲 100 亿次）；DeepSHAP = 听完整首曲子后反向分析每个音符的贡献（一次弹奏）

### 3.5 三种算法对比

| 维度                     | KernelSHAP         | TreeSHAP               | DeepSHAP               |
| ------------------------ | ------------------ | ---------------------- | ---------------------- |
| **适用模型**             | 任意模型           | 树模型                 | 神经网络               |
| **计算精度**             | 近似估计           | 精确                   | 近似估计               |
| **计算复杂度**           | $O(N \cdot 2^d)$   | $O(TLD^2)$             | $O(N \cdot L)$         |
| **核心方法**             | 采样 + 线性回归    | 树结构动态规划         | 反向传播               |
| **绕开指数复杂度的方式** | 用统计估计代替穷举 | 用结构特性避免枚举子集 | 用链式法则避免重复计算 |

**一句话总结**：
- **KernelSHAP**：不算那么细，用采样猜答案
- **TreeSHAP**：树已经记住了所有组合，直接查表
- **DeepSHAP**：像算梯度一样算归因，一次反向传播搞定

## 4. 可视化与解读

### 4.1 Summary Plot (Beeswarm)

最重要的图。展示了：
- 每个特征对预测的重要性排序（从上到下递减）
- 每个点代表一个样本
- 颜色 = 特征值（红=高，蓝=低）
- 水平位置 = SHAP 值（对"预测为欺诈"的贡献，正值→推向欺诈）

**解读示例**：
- 如果 V4 在最顶部，红色点偏右，蓝色点偏左
- → V4 的值越高，越倾向于预测为欺诈 → 这是逻辑上合理的

### 4.2 Waterfall Plot（瀑布图）

展示**单个预测**的特征贡献分解：

```
Base value (population mean)  ─────  0.01
  + V4 = 2.3                 ───── +0.15
  + V14 = -1.7               ───── +0.08
  + Amount = 149.99          ───── -0.03
  ...
  = Final prediction         ─────  0.87  → 判定为欺诈
```

### 4.3 Dependence Plot

展示单个特征的值与其 SHAP 值的关系，可以揭示非线性效应和交互效应。

### 4.4 Bar Plot

各特征 SHAP 值绝对值的均值排序——最简洁的"特征重要性排名"。

## 7. SHAP 的局限性

- **计算成本**：KernelSHAP 对深度模型计算极慢
- **特征依赖假设**：SHAP 假设特征独立，在强相关特征上可能产生误导性结果
- **解释不等于因果**：SHAP 告诉模型依赖了什么，但不应被解读为因果关系
- **人类解读偏差**：即使 SHAP 提供了客观的归因，分析者仍可能选择性地关注支持其先验信念的特征
- **只衡量个体贡献**：SHAP 无法捕捉特征间的交互效应（协同/冗余），这是 2024 年研究的热点改进方向

## 8. 前沿改进：Shapley Interaction Index（SII）

### 8.1 为什么需要交互分析？

SHAP 只回答"每个特征贡献了多少"，但无法回答"两个特征的组合是否比各自独立之和更有信息量"。

**业务示例**：

```
SHAP 告诉你：
  - "年龄" 贡献 +0.15
  - "收入" 贡献 +0.12

SII 告诉你：
  - "年龄 + 收入" 二阶交互 = -0.08（冗余效应）
  → 年轻人高收入的信息重叠了，模型可能过度依赖这个组合

业务意义：
→ 可以优化风控规则：单独制定"年轻高收入"客群的专项策略
→ 发现潜在的数据冗余，指导特征工程
```

### 8.2 离散导数与交互的纯度量

对于特征对 {i, j}，其纯交互效应（剥离低阶影响）：

$$\Delta_{ij}(T) = \nu(T \cup \{i,j\}) - \nu(T \cup \{i\}) - \nu(T \cup \{j\}) + \nu(T)$$

- **正值** → 协同效应（两个特征组合比各自独立之和更有信息量）
- **负值** → 冗余效应（两个特征信息重叠）

### 8.3 shapiq 工具包

`shapiq` 是 2024 年发布的统一 Shapley 交互分析框架，支持：

| 功能 | 说明 |
|------|------|
| k阶 SII | 最直接的扩展，计算所有 ≤k 阶的交互（默认推荐） |
| STII | 高阶交互效应"浓缩"到 k 阶（关注最强组合） |
| FSII | 最小二乘最优近似（追求最佳拟合精度） |
| TreeSHAP-IQ | 树模型专用，O(TL·2^k) 精确计算 |

```python
import shapiq

# 对 XGBoost 计算二阶交互
explainer = shapiq.TreeExplainer(model=xgb_model, max_order=2)
interaction_values = explainer.explain(x=X_test[:10])

# 获取二阶交互
second_order = interaction_values.get_n_order_values(2)

# 获取最强的交互组合
top_pairs = interaction_values.top_k(k=5)
for (i, j), value in top_pairs.items():
    if value > 0:
        print(f"({feat[i]}, {feat[j]}): 协同效应 +{value:.4f}")
    else:
        print(f"({feat[i]}, {feat[j]}): 冗余效应 {value:.4f}")

# 网络图可视化
interaction_values.plot_network(feature_names=FEATURE_NAMES)
```

### 8.4 可视化增强

shapiq 提供的**交互网络图**：
- **节点大小** = 一阶特征重要性（SHAP 值）
- **边的粗细** = 二阶交互强度
- **边的颜色** = 协同（正）/ 冗余（负）
