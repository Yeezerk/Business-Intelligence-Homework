# 06 — 评估指标的商业视角

> **核心问题**：Accuracy 99.9% 的模型可能毫无商业价值。在不平衡的欺诈检测中，选对评估指标比选对模型更重要。

---

## 1. 从混淆矩阵开始

|  | 预测正常 | 预测欺诈 |
|--|---------|---------|
| **实际正常** | TN（正确放行） | FP（误报/错误拦截） |
| **实际欺诈** | FN（漏报/未检出） | TP（正确拦截） |

### 1.1 四类结果

- **TN**：正常交易，模型说正常 → 用户开心支付
- **FP**：正常交易，模型说欺诈 → 用户被误拦，打电话投诉
- **FN**：欺诈交易，模型说正常 → 钱丢了
- **TP**：欺诈交易，模型说欺诈 → 成功拦截

### 1.2 业务成本的差异

在银行的实际运营中：
- 一次 FP：客服人员审查 → 耗时 5 分钟 → 成本约 \$2-5
- 一次 FN：资金损失 + 赔付 + 声誉损害 → 成本可能 \$100-1000+

**FN 的成本通常是 FP 的 10-100 倍。**

---

## 2. 为什么 ROC-AUC 会骗你？

### 2.1 ROC 曲线的定义

- X 轴：FPR = FP / (FP + TN) — 正常交易被误拦的比例
- Y 轴：TPR = TP / (TP + FN) — 欺诈交易被检出的比例

### 2.2 不平衡时的陷阱

假设 100,000 交易，100 笔欺诈：

| 模型 | 预测 | FPR | TPR | Accuracy |
|------|------|-----|-----|----------|
| 全猜正常 | 全 0 | 0/99900 = 0 | 0/100 = 0 | 99.9% |
| 抓到 90，误报 1000 | 混合 | 1000/99900 ≈ 1% | 90/100 = 90% | 98.9% |

模型A：ROC-AUC ≈ 0.5（随机线），Accuracy 99.9%
模型B：ROC-AUC ≈ 0.94，Accuracy 98.9%

ROC-AUC 能区分优劣！但看 Accuracy 会被欺骗。

### 2.3 ROC-AUC 的真正问题

问题不在 ROC-AUC 本身，而在于**差值被稀释**：

- 两个模型在 99,900 个 TN 上的表现完全相同 → FPR 计算中这些 TN 是分母
- 即使模型B 比模型A 多检出 90% 的欺诈，ROC-AUC 的差异可能只有 0.005
- 当欺诈比例从 0.1% 变为 0.5%，ROC-AUC 基本不变但 PR-AUC 变化显著

---

## 3. PR 曲线和 AUPRC

### 3.1 PR 曲线的定义

- X 轴：Recall = TP / (TP + FN)
- Y 轴：Precision = TP / (TP + FP)

PR 曲线**不包含 TN**。这意味着正常交易的数量对曲线不产生影响。

### 3.2 AUPRC 的公式

AUPRC（Area Under the Precision-Recall Curve）是 PR 曲线下的面积，没有解析公式，是一个数值积分：

$$AUPRC = \int_0^1 p(r) \, dr$$

实际计算时，对所有阈值点做求和：

$$AUPRC = \sum_{n} (R_{n+1} - R_n) \cdot P_n$$

其中：
- $R$ = Recall = TP / (TP + FN)
- $P$ = Precision = TP / (TP + FP)

**与 ROC-AUC 的公式对比**：

$$ROC-AUC = \int_0^1 TPR(FPR) \, d(FPR)$$

**关键区别**：ROC-AUC 可以解析计算（只需排序后统计逆序对），而 AUPRC 必须数值积分。

**代码实现**（sklearn）：

```python
from sklearn.metrics import average_precision_score
auroc = average_precision_score(y_true, y_scores)
```

### 3.3 AUPRC 的数学含义

可以从两个角度理解：

**几何角度**：PR 曲线下的面积越大，说明模型在**不同召回水平下都能保持较高精确率**。

**概率角度**：AUPRC ≈ **随机抽取一个正类样本，模型给它比随机负类样本更高分数的概率**。

$$AUPRC = \frac{1}{|P|} \sum_{i \in P} \frac{|\{j \in N : s_j < s_i\}|}{|N|}$$

其中 $P$ 是正类集合，$N$ 是负类集合，$s_i$ 是模型分数。

### 3.4 为什么 AUPRC 更适合不平衡数据

- AUPRC 的变化直接反映"模型在找欺诈交易方面做得多好"
- 不受"有多少正常交易"的影响
- 对类别分布变化敏感（更接近现实——如果欺诈比例翻倍，AUPRC 会变，ROC-AUC 不会）

### 3.3 什么时候用哪个？

| 场景 | 推荐指标 |
|------|---------|
| 极度不平衡（< 1%） | AUPRC（首选） |
| 需要与文献对比 | ROC-AUC（文献广泛使用） |
| 需要选定一个决策阈值 | F1-Score @ best threshold |
| 业务决策 | Cost Matrix |
| 平衡数据 | ROC-AUC 和 AUPRC 都可以 |

## 4. 成本敏感评估

### 4.1 为什么需要成本矩阵？

AUPRC 告诉你"模型找欺诈的能力"，但不告诉你"误报了多少". 

两个模型都可能 AUPRC=0.85：
- 模型A：高 Precision 低 Recall（只拦最确定的，放过大量可疑的）
- 模型B：高 Recall 低 Precision（宁可错杀一千，不放过一个）

哪个更好？取决于业务场景。

### 4.2 本项目中的成本函数

```python
cost = FP × 1 + FN × 10
```

**作用有两个层面**：

**评估层面：选择最佳阈值**

遍历不同阈值，找到让 cost 最小的阈值作为决策边界，比基于 F1 最大化更贴合业务。

**业务含义**

| 错误类型 | 成本 | 含义 |
|---------|------|------|
| FP（误报） | × 1 | 正常用户被误拦，打电话解释，客服成本 |
| FN（漏报） | × 10 | 欺诈交易未被拦截，资金损失 |

**10:1 的比例** 说明：漏掉一个欺诈的代价 = 误拦 10 个正常用户的代价。

如果业务更注重用户体验（如不想流失客户），可以调高 FP 的权重；如果更注重风险控制（如金融场景），可以调高 FN 的权重。

**为什么不用 F1 而用成本？**

F1 = 2 × (P × R) / (P + R)，给 Precision 和 Recall 同等权重。但业务上 FN 通常比 FP 贵得多。成本函数让模型在**宁可多误报一点，也要少漏报**的方向优化。

可以根据实际业务调整权重。如果银行更在意用户体验（不想误拦），可以把 $C_{FP}$ 调高。

## 5. 阈值选择

模型输出的是概率 $p \in [0, 1]$，需要选定阈值 $t$ 来做出二分类决策。

### 5.1 默认阈值 0.5 的问题

在极度不平衡数据上，模型通常不太可能输出 $p > 0.5$。如果正类只占 1%，模型学到的最优 $p$ 分布可能集中在 0.001-0.01。

### 5.2 最佳阈值的选择方法

**基于验证集 F1 最大化**：

```python
from sklearn.metrics import precision_recall_curve
precision, recall, thresholds = precision_recall_curve(y_val, y_scores)
f1_scores = 2 * precision[:-1] * recall[:-1] / (precision[:-1] + recall[:-1])
best_threshold = thresholds[f1_scores.argmax()]
```

**基于业务成本最小化**：

```python
for t in thresholds:
    y_pred = (y_scores >= t)
    fp = ((y_pred == 1) & (y_val == 0)).sum()
    fn = ((y_pred == 0) & (y_val == 1)).sum()
    cost = fp * C_FP + fn * C_FN
    best_t = thresholds[costs.argmin()]
```

成本最优化方法直接对齐业务目标。

## 8. 前沿补充：校准与不确定性量化

### 8.1 为什么概率校准很重要？

当前评估只关注排序能力（AUPRC）和分类能力（F1），但忽略了**概率的可靠性**：

```
模型 A 说："这笔交易 80% 是欺诈" → 实际欺诈率 80% → 校准良好
模型 B 说："这笔交易 80% 是欺诈" → 实际欺诈率 40% → 校准不良（过度自信）

两个模型的 AUPRC 可能相同，但模型 B 在业务中更危险：
→ 过度自信导致审核资源分配不当
→ 监管审计时无法合理解释"80%"的含义
```

### 8.2 Expected Calibration Error (ECE)

$$\text{ECE} = \sum_{b=1}^{B} \frac{n_b}{N} |acc(b) - conf(b)|$$

- 将预测概率分为 B 个等宽桶
- 每个桶计算实际正类率与平均置信度的差距
- ECE = 0 表示完美校准

**可靠性图（Reliability Diagram）**：横轴为预测概率，纵轴为实际正类率。对角线表示完美校准，偏离对角线越远校准越差。

### 8.3 校准方法

| 方法 | 原理 | 适用场景 |
|------|------|---------|
| **Platt Scaling** | 用逻辑回归 $σ(a \cdot z + b)$ 校准输出 | 通用，简单 |
| **Isotonic Regression** | 非参数单调回归校准 | 校准误差非线性的情况 |
| **Temperature Scaling** | 输出除以标量 $T$：$z/T$ | 深度模型专用，极简 |

```python
from sklearn.calibration import calibration_curve, CalibratedClassifierCV

# 方法1：绘制可靠性图
prob_true, prob_pred = calibration_curve(y_test, y_scores, n_bins=10)

# 方法2：Platt Scaling 校准
calibrated = CalibratedClassifierCV(xgb_model, method='sigmoid', cv='prefit')
calibrated.fit(X_cal, y_cal)
calibrated_scores = calibrated.predict_proba(X_test)[:, 1]

# 方法3：Isotonic Regression 校准
calibrated_iso = CalibratedClassifierCV(xgb_model, method='isotonic', cv='prefit')
calibrated_iso.fit(X_cal, y_cal)
```

### 8.4 Conformal Prediction（保形预测）

2024 年金融 AI 的热门方向，提供**分布无关的覆盖率保证**：

- 不假设数据分布
- 给出预测集（而非点估计），保证真实标签以 $(1-\alpha)$ 的概率落入预测集
- 适用于任何预训练模型（作为后处理步骤）

**业务价值**：
- "我们有 90% 的把握认为这笔交易属于{欺诈}集合" → 比单纯概率更有监管说服力
- 可以根据覆盖率要求动态调整审核策略
